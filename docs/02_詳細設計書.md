# kenecho Village 詳細設計書

バージョン：1.0　／　状態：確定（実装開始時点）
本作品は研修・学習用途のローカルWebアプリです。数値・助言は医療・栄養・心理・人格の診断ではありません。

---

## 1. 技術方針

- 言語：HTML / CSS / JavaScript（ES2017+ 相当、ブラウザ標準文法のみ）
- 外部依存：なし（フレームワーク・API・CDN・画像・フォント・fetch を一切使わない）
- 実行形態：`index.html` を `file://` で直接開く。classic `<script>` タグを依存順で読み込み、ES Modules は使わない
- 名前空間：各 JS は `globalThis` へ公開（例 `globalThis.KE_CONFIG`）。Node.js テストのために CommonJS 互換ラッパーを持つ
- データ保存：`localStorage`（キー `kenechoVillage.db.v1`）
- 画面遷移：SPA方式。`index.html` 内に全画面のコンテナを用意し、`ui.js` / `app.js` が表示切替する（URL遷移・ルーティングなし）

### レコード型
- `MealRecord`：`{ id, foodId, name(保存時スナップショット), mealType:"breakfast|lunch|dinner|snack", baseQty, unit, actualQty, kcal, protein, fat, carbs, isCustom }`
- `ExerciseRecord`：`{ id, exerciseId, name, minutes, calories, calcMode:"mets|manual" }`
- `FoodDef`：`{ id, name, category, kcalPer100g, proteinPer100g, fatPer100g, carbsPer100g, unitName, baseAmountGram }`（プリセットも同型）
- `ExerciseDef`：`{ id, name, mets, note }`
- `PetMemory`：`{ generationId, name, speciesId, birthDate, hatchedAt, departedAt, daysTogether, finalStage, healthRecordDays, questDays, finalBond, mainNpcId }`

### 保存ユーティリティ
- `KE_DB.save()`：スキーマ全体を `JSON.stringify` して保存。失敗時 `try/catch` でユーザーへ通知し、書き込み前の値を保持
- `KE_DB.load()`：読み込み→ `JSON.parse` → スキーマ検証 `validateSchema(data)` → 不足項目を初期値で補完（マイグレーション）
- 検証失敗（`data` が非オブジェクト・`schemaVersion` 不一致・必須型を満たさない） → `KE_DB.quarantine()` で `kenechoVillage.db.corrupt.<ts>` へ退避してから `KE_DB.defaultData()` で起動
- データ初期化は `KE_DB.resetData()`：確認モーダル通過後に削除→初期値保存

## 5. 画面遷移

- 起動：`app.js` → `DB.load()` → プロフィール未作成なら S01 初期設定を最初から表示 → 作成済みなら S02 ホーム
- 画面は `data-screen` 属性のコンテナ群。`KE_UI.showScreen(id)` が対象以外を非表示化
- トップバー：ロゴ（ホームへ戻る）／記録／ペット／会話クエスト／交流ノート／思い出／図鑑／設定／「研修用・本番利用不可」
- 条件分岐遷移：
  - 記録タブ：食事/運動/睡眠/体重
  - ペット画面：卵状態なら外出→孵化遷移、それ以外はペット小屋
  - 会話クエスト：未確定の卵があれば種類公開後へ誘導（NPCは未公開）
  - 練習モード：会話画面内のタブ切り替え
- モーダルは `overlay + dialog[role=dialog]`。確認系は `aria-modal=true`

## 6. 状態遷移

### 6.1 ペット成長
```
egg --(初回外出の孵化イベント)--> child(幼体)
child --(累計EXP>=150 かつ 孵化後>=3日)--> growing(成長期)
growing --(累計EXP>=450 かつ >=7日)--> adult(成体)
adult --(累計EXP>=800 かつ >=14日)--> companion(陪伴期)
companion --(累計EXP>=1200 かつ >=21日 かつ ペットきずな度>=60)--> departure(旅立ち可)
departure --(旅立ちイベント)--> 思い出保存 --> 新卵(new generation: gen_00X, stage=egg)
```
- 段階判定は `KE_PET.getStage(cumulativeExp, hatchedAt, today)` を日付ロールオーバー時に判定・反映
- 成長判定タイミング：日次評価確定後・アプリ起動時・デモツールの日付進行後

### 6.2 種類非公開 → 公開
```
currentPet.stage=egg かつ speciesRevealed=false
→ 外出ボタン（ペット小屋）→ village entrance 画面
→ 孵化演出（animation.egg_hatch）
→ 決定方式へ分岐
   choose: 6候補を表示（ピクセル・コーチタイプ・短い説明）→ 1つ選択
   random: 候補からランダム1種
→ speciesId 決定＋ speciesRevealed=true ＋ petEncyclopedia[speciesId]={discovered:true, discoveredAt:today} を
   同一 `KE_DB.save()` 内で原子的に更新（途中離脱なら未確定状態のまま卵を維持）
→ 種類公開演出 → 最初のNPCとの出会い演出（交流ノートへ初遭遇登録）
```
- 乱数シードは保存しない（再現性はテスト用に `KE_UTIL.rand` を注入可能にする）
- 次世代の候補除外：`KE_PET.getSelectableSpecies(previousSpeciesId)` が直前世代の種類を除外

### 6.3 今日の会話クエスト
```
conversation.dailyQuestDate === today ?
  └ YES: 再プレイ可（きずな度更新なし・報酬なし）
  └ NO : シーン選択（未遭遇NPCのシーンを含む）→ 1ターン3択 → 回答評価
        → NPCきずな度更新（+8/+3/−4、0-100補正）
        → ペットきずな度 +2（未実施の場合）
        → relationshipHistory へ記録
        → conversation.dailyQuestDate=today, dailyQuestCompleted=true
```
- NPC別・ペット別に「1日1回」を判定するため、`conversation.dailyQuestDate` と `relationships.*` を照合。既に更新済みなら数値更新と `relationshipHistory` 追記を行わない

### 6.4 会話練習モード
- シーン選択 or ランダム → 4ターン実施（各ターン3択から選択→NPC反応・解説を確認）→ 条件成立時は5ターン目（ボーナス）を実施
- ボーナス成立条件：4ターン中「会話が続きやすい（good）」を2回以上選んだ場合
- きずな度・履歴・EXPは一切更新しない

## 7. 計算仕様

### 7.1 BMI・基礎代謝
- BMI ＝ `weightKg / Math.pow(heightCm / 100, 2)`（小数第1位表示）
- 基礎代謝（Mifflin–St Jeor、成人、kcal/日）：
  - 男性：`10*weight + 6.25*heightCm - 5*age + 5`
  - 女性：`10*weight + 6.25*heightCm - 5*age - 161`
- 使用体重：最新日付の体重記録、なければ初期設定時の `profile.weightKg`
- 注意表示：推定値であり個人差がある。医療診断ではない

### 7.2 食事の按分
- `ratio = actualQty / baseAmountGram`（基準分量1つ分に対する割合）
- kcal ＝ `kcalPer100g × baseAmountGram/100 × ratio`（蛋白質・脂質・炭水化素も同様、小数第1位で保存）

### 7.3 運動の消費カロリー
- 推定式：`kcal = METs × 3.5 × weightKg / 200 × minutes`（小数第1位）
- 計算に使う体重は最新体重（記録時点での適用推奨）。計算式と単位は画面に注記表示
- `calcMode:"manual"` の場合は入力値をそのまま使用

### 7.4 睡眠時間
- `hours = (wakeAsMinutes + 24×跨ぎ補正 - sleepAsMinutes) / 60`
- 起床時刻が就寝時刻未満（日跨ぎ）なら +24h
- 就寝時刻 === 起床時刻 の場合は保存エラー「就寝時刻と起床時刻が同じです」

### 7.5 日次健康スコア（各0〜2）
| 項目 | 0点 | 1点 | 2点 |
| --- | --- | --- | --- |
| 食事 | その日の食事記録が0件 | 記録あり | 記録あり かつ 総カロリー≦ 上限 かつ 総蛋白質 ≧ 目標 |
| 運動 | 記録なし | 記録あり | 記録あり かつ 総運動時間 ≧ 目標 |
| 睡眠 | 記録なし(または基準外) | 記録あり | 睡眠時間 ≧ 目標 |

- 蛋白質目標は設定値、未設定なら `round(体重kg × 1.0)` g

### 7.6 健康EXP
- `score EXP` 表を `SCORE_EXP_TABLE` で参照（未記録→0）
- 確定操作：日次評価画面で「今日の結果を確定」→ `dailyEvaluations[today] = {granted:true,...}`、`currentPet.cumulativeExp += exp`、`recordedDays += 1`
- 二重付与禁止：`dailyEvaluations[today].granted === true` なら再加算しない
- 過去日付の記録編集は `dailyEvaluations` を再計算しない（統計表示のみ再計算）
- EXP 開始時の成長段階チェックもこのタイミングで実施

  npcId: "npc_suzuki", background: "outdoor", // office|elevator|breakroom|dining|outdoor

### 8.3 コーチ台詞
- `id`：`coach_<pet>_<purpose>_<n>`（例 `coach_rabbit_feedback_001`）
- フィールド：`petTypes[] / coachTypes[] / growthStages[] / petConditions[] / answerType / sceneTags[] / relationLevels[](NPC) / petRelationLevels[] / purpose`（`greeting|feedback|encourage|special|departure` 等）/ `text / weight`
- 抽選：`KE_DIALOGUE.pick(ctx)` が 条件合致候補 → 重み付きランダム。連続回避のため直近10IDを除外

## 9. 健康状態（ペット表示用）

- `KE_PET.getCondition(healthRecords, healthGoals, today, pet)`：
  - 今日の睡眠時間 < sleepHours × 0.5 → `sleepy`（眠そう）を優先
  - 睡眠・運動・食事すべて満点（2点）→ `perfect`（絶好調）
  - 睡眠・運動・食事のいずれかが2点 → `happy`（ご機嫌）
  - 記録の有無で判断し、今日の記録が0件 → `lonely`（少し寂しそう）
  - それ以外 → `normal`（ふつう）
- 構成キー：`perfect|happy|normal|lonely|sleepy`（日本語ラベルはUI層で対応）

## 10. アニメーション仕様

- ピクセル定義：`js/data/pixel-art/*.js` に32×32の配色マス配列（文字→色keyのパレット）
- `KE_SPRITE.render(specKey, frame)`：Canvas を作成し最近傍補間で整数倍（3〜4倍）拡大描画。キャッシュし再利用
- `animation-manifest.js`：
```javascript
{ pet: { rabbit: { idle: { frames: 4, fps: 4, priority: 7 },
                   blink: { frames: 4, fps: 4, ... }, ... } }, ... }
```
- `KE_ANIMATION.play(element, specKey, animName)`：リクエストによらずキューの優先順位（数字が小さいほど高優先）で横取り再生。終了後は健康状態の待機動作へ戻す
- 優先順位：成長・旅立ち(0) > 孵化・種類公開(1) > 記録・会話結果(2) > 食事・運動(3) > 会話中(4) > 健康状態(5) > 通常待機(6)
- `prefers-reduced-motion: reduce` では最初の1フレームだけ表示しループ停止。アニメなしでも状態が分かるよう、状態アイコン・文字との併用

## 11. イベント（代表）

| イベント | 発火 | 処理 |
| --- | --- | --- |
| `app:start` | 起動 | DBロード→初期設定判定→画面表示 |
| `setup:submit` | 初期設定完了 | profileId 生成・初期DB保存 |
| `record:save` | 各記録フォーム | 検証→保存→スタンプ演出→合計・評価再描画 |
| `record:evaluate` | 評価確定ボタン | スコア算出→EXP付与（二重禁止）→成長判定→演出 |
| `pet:hatch` | 外出→孵化 | 孵化演出→種類決定→図鑑登録（原子的） |
| `quest:answer` | 3択選択 | 回答評価→NPC反応→きずな度更新（1日1回）→台詞抽選→演出 |
| `practice:answer` | 練習中選択 | 解説表示（きずな度不変）→次ターン |
| `pet:depart` | 旅立ち決定 | 思い出保存→新卵生成→演出 |
| `settings:reset` | データ初期化 | 確認→全削除→初期値で再起動 |

## 12. エラー処理

- 入力エラー：各入力欄直下へ文章表示（例「体重は20.0〜300.0kgの範囲で入力してください」）
- 保存失敗：`localStorage` が throw した場合 `KE_DB.save` が握り、通知。データ破損時は隔離→初期値
- 未来日付：選択日が今日より未来なら登録不可のエラー
- 破損データ：隔離キーへ移動し安全な初期値で起動（初回表示で通知）
- 不正な値（NaN・範囲外）はフォーム検証で遮断。ロジック層でも丸め・補正

## 13. セキュリティ実装

- `innerHTML` は静的テンプレートのみに使用し、ユーザー入力・DB由来文字列は必ず `textContent` / `setAttribute` 経由
- localStorage キーは `kenechoVillage.` プレフィックスに限定
- 外部通信なしを保証（コード中に fetch/XMLHttpRequest/CDN URL を含めない）

## 14. 研修デモツール

設定画面内タブに実装。
- 今日の記録の「そのまま評価」を強制（スコア注記）
- 「EXP ＋100」実行（1日上限を一時的に無視して付与 ※デモ専用）
- 「孵化日から n 日進める」による段階判定再実行
- 「旅立ちを実行」ボタン（条件未達でも実行、思い出保存と次世代開始は通常処理を再利用）
- 「データ初期化」ボタン（確認経由）

全操作後に `relationshipHistory`・`dailyEvaluations` は通常ルールのまま扱うが、デモ操作を行った旨は画面注記へ表示する。

## 15. テスト対応（詳細は 04_テスト仕様書.md）

- `tools/tests/` に Node 標準テストを配置。`package.json` の `"test": "node --test tools/tests/"` を想定（package.json はテスト実行のみに使用し、実行時依存は持たない）
- ロジック層（health/pet/relationship/dialogue/conversation/db）は `require()` で読み出せる型で実装し、ブラウザ依存をUI層に閉じ込める
- データ整合テスト：件数（食品50・運動20・シーン20・NPC8・台詞150〜180）、ID一意・参照整合（npcId/sceneId/foodId 等）を検証

## 16. 実装時の確定事項・差分メモ（M16 時点で同期）

実装の過程で下記を確定した。設計文書・テスト・実装はすべてこの内容で揃えてある。

1. **台詞データ**：単純列挙でなく、6種の「声」と条件パターンからビルダーで152件を生成（フィードバック9×種類＋状態4＋シーン3＋イベント3＋挨拶、コーチ×分類18、分類3、関係段階10、フォールバック1）。ID は一意。件数は100〜300（目標150〜180）をテストで担保。
2. **会話シーン**：20シーンを `scn_001`〜`scn_020` で採番し、NPC の `sceneIds` と双方向で一致させるテストを追加。各シーンは練習用に4ターン（各ターン3択）を持ち、クエストは `rounds[0]` を使う。
3. **練習モードのボーナスタン**：シーンごとに持つのではなく、エンジンが共通の「締めの一言」を用意し、good が2回以上で1回だけ追加する。
4. **スプライト**：`js/data/pixel-art/pets.js` の共通ボディ＋種類別アクセサリ（耳・しっぽ）＋表情フレーム（normal/blink/happy/sleepy/troubled/talk/eat）を `sprite.js` がモーション・フレームで合成する実行時描画。NPC は現段階では仮シルエット（M14 時点）。
5. **孵化フロー**：村の入口で卵を `egg_hatch` アニメーションでかえし、その後「自分で選ぶ／おまかせ」へ。途中離脱時は卵状態を維持（決定処理を保存しないため）。
6. **最初のNPC**：種類公開（図鑑登録）と同じ保存処理で `npc_sato` との出会いを登録する（NPCは公開前に登場しない）。
7. **研修デモツール**：設定画面に EXP付与／孵化日を7日前へ／強制孵化／旅立ち強制／データ初期化を実装。旅立ち強制と EXP付与は通常処理を再利用する。
8. **ローカルデータ**：`kenechoVillage.db.v1` に統一スキーマで保存。破損は隔離キー `kenechoVillage.db.corrupt.*` へ退避し初期値で起動。保存失敗（Quota等）は `save()` が false を返して通知し、メモリ状態を維持する。
