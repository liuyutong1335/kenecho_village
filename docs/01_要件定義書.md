# kenecho Village 要件定義書

バージョン：1.0　／　状態：確定（実装開始時点）

本作品は研修・学習用途のローカルWebアプリです。表示する数値・助言は医療・栄養・心理・人格の診断ではありません。

---

## 1. プロジェクト概要

- 作品名：**kenecho Village ― 健康と会話で育てるピクセルペット ―**
- 形態：HTML / CSS / JavaScript のみのローカルWebアプリ（サーバ不要・データ送信なし・外部依存なし）
- 対象ブラウザ：PC版 Microsoft Edge / Google Chrome の最新版
- データ：localStorage（1ブラウザにつき1プロフィール）
- 個体・キャラクター・会話・食品・運動は全て架空のオリジナル

### 目的

食事・運動・睡眠・体重の健康記録と、電子ペット育成、NPCとの会話練習を組み合わせる。
健康記録によってペットが成長し、ペットと一緒に架空NPCとの会話クエストへ参加する。
ユーザーは3つの返答から1つを選び、NPCの反応とペット固有のアドバイスを確認しながら、
会話を続ける方法を楽しく体験する。健康記録と会話練習に、ペット育成・NPCとの関係・
世代交代・収集要素を加えることで、継続利用の動機を高める。

### 中心ループ

```
健康記録 → 健康EXP獲得 → ペット成長 → ペットと外出 → NPCとの会話クエスト
→ 3択回答 → NPCの反応 → ペットのアドバイス → きずな度上昇
→ 特別会話・思い出 → ペットの旅立ち → 新しい卵 → 次世代
```

## 2. 対象ユーザー（ペルソナ）

| 項目 | 設定 |
| --- | --- |
| 表示名 | 高橋 翔太（架空） |
| 年齢 | 23歳 |
| 属性 | 入社1年目の会社員 |
| 課題 | 健康記録が長続きしない／職場や日常の短い会話で返答に迷う |
| 目的 | ペットを育てながら健康記録と会話練習を続けたい |

開発・テスト・デモでは、実在人物・企業・顧客・勤務情報・実際の健康記録を使用しない。

## 3. 対象範囲

- 初期設定（分割入力、`profileId` 生成）
- 健康記録：食事／運動／睡眠／体重（過去日付の編集を含む）
- 健康目標の設定と、BMI・基礎代謝の表示
- 日次健康評価と健康EXP付与
- ペット育成：卵→幼体→成長期→成体→陪伴期→旅立ち→次世代
- 初回外出による孵化と種類公開（自分で選ぶ／おまかせ）
- 架空NPC 8名との会話クエスト（1日1回）と会話練習モード（任意回数）
- きずな度（NPC別・ペット世代別・総合）と関係段階
- 交流ノート・ペット図鑑・思い出（世代記録）
- 保存・復元・破損データ隔離・データ初期化
- 研修デモツール（生成循環の確認用）

## 4. 対象外（スコープ外）

- 複数プロフィールの切り替え（第1版は1ブラウザ1プロフィール）
- サーバ連携・同期・オンライン機能
- ログイン・アカウント管理
- 医療・栄養・心理・人格の診断・判定・保証
- 実際の食品・運動データベースとの連携（プリセットは架空の参考データ）
- 音声合成・外部フォント・外部画像
- スマートフォン・タブレット向け最適化（PCのChrome/Edgeを対象）
- 回答選択肢の正誤判定（「続きやすい／続きにくい」は参考提示に留める）

## 5. 機能要件

### FR1 初期設定
- FR1.1 分割された入力画面で以下を登録する：ユーザー表示名／年齢／性別／身長／体重／第1世代ペット名／ペット決定方式（自分で選ぶ・おまかせ）
- FR1.2 この時点でペット種類は表示・決定しない
- FR1.3 完了時にランダムな内部 `profileId` を生成し localStorage へ保存。表示名変更で `profileId` は変わらない

### FR2 健康記録（食事）
- FR2.1 プリセット食品約50件を収録し、食品名で検索できる
- FR2.2 朝食／昼食／夕食／間食の分類を持ち、基準分量と実摂取量から熱量・蛋白質・脂質・炭水化物を按分計算する
- FR2.3 記録の追加・編集・削除、カスタム食品の追加・編集・削除・再利用
- FR2.4 日付別の一覧と合計を表示する

### FR3 健康記録（運動）
- FR3.1 プリセット運動約20件を収録し、運動名・時間・体重・METsにより消費カロリーを推定
- FR3.2 消費カロリーの直接入力も可
- FR3.3 記録の追加・編集・削除、カスタム運動の追加・編集・削除
- FR3.4 日付別の合計時間と消費カロリーを表示

### FR4 健康記録（睡眠）
- FR4.1 入眠時刻と起床時刻を記録（起床日基準・日跨ぎを正しく計算）
- FR4.2 就寝時刻と起床時刻が同じ場合は保存しない
- FR4.3 追加・編集・削除、日付別睡眠時間表示

### FR5 健康記録（体重）
- FR5.1 日付と体重を記録。1日1件。同日の再登録は上書き確認
- FR5.2 追加・編集・削除、全履歴保存、直近30日程度のトレンドグラフ
- FR5.3 最新体重によりBMI・基礎代謝を再計算

### FR6 過去日付
- FR6.1 食事・運動・睡眠・体重は過去日付への追加・編集・削除が可能
- FR6.2 過去日付の変更は健康記録と統計に反映するが、確定済みの健康EXP・きずな度・会話報酬は再計算しない
- FR6.3 未来日付は登録できない

### FR7 健康目標・計算
- FR7.1 目標設定：1日の摂取カロリー上限／蛋白質目標／運動時間目標／睡眠時間目標
- FR7.2 未設定時は初期値を使用（初期値は詳細設計書に定義）
- FR7.3 BMI ＝ 体重kg ÷ 身長m²（最新の体重記録を使用、なければ初期設定時の体重）
- FR7.4 基礎代謝は成人用 Mifflin–St Jeor 式を使用。採用式・注意事項・単位を設計書と画面に記載し、医療診断として表示しない

### FR8 健康評価とEXP
- FR8.1 食事・運動・睡眠を各0〜2点、合計0〜6点で評価
- FR8.2 日次評価確定時のみEXP付与（下表）。1日上限100。同日の二重付与禁止
- FR8.3 過去記録の変更で再計算しない
- FR8.4 会話クエストではEXPを付与しない

| 健康スコア | EXP |
| ----: | --: |
| 未記録 | 0 |
| 0 | 15 |
| 1 | 25 |
| 2 | 40 |
| 3 | 55 |
| 4 | 70 |
| 5 | 85 |
| 6 | 100 |

### FR9 ペット育成
- FR9.1 成長段階：卵→幼体→成長期→成体→陪伴期→旅立ち
- FR9.2 成長閾値・最低経過日数・旅立ち条件は詳細設計書で決定し、定数を `js/config.js` へ集約
- FR9.3 研修デモで世代循環を確認できるテスト手段を用意する

### FR10 卵と種類非公開
- FR10.1 卵取得時は種類を決定しない（`speciesId: null` / `speciesRevealed: false`）
- FR10.2 家の中では種類名・種類別スプライト・色や模様・種類別台詞・種類別説明を一切表示しない
- FR10.3 卵段階は共通の卵スプライトを使用し、図鑑へは登録しない
- FR10.4 初回外出（ペット小屋→外へ出る→村の入口）で孵化イベントを発生させる
- FR10.5 孵化演出後に「自分で選ぶ／おまかせ」で種類を決定し、公開・図鑑登録する
- FR10.6 NPCは種類公開前に登場しない
- FR10.7 おまかせは利用可能な種からランダム。次世代は直前世代と同じ種類を候補から除外
- FR10.8 種類確定と図鑑登録は同一処理として保存。途中で画面を閉じた場合、未確定なら卵状態を維持
- FR10.9 この仕様をすべての世代に適用

### FR11 ペット状態
- FR11.1 健康記録により絶好調／ご機嫌／ふつう／少し寂しそう／眠そうを表示
- FR11.2 睡眠時間が目標の半分未満の場合は「眠そう」を優先
- FR11.3 健康状態は表情・待機動作・台詞の前置きに影響するが、会話評価やきずな度の増減には影響させない

### FR12 会話クエスト
- FR12.1 架空シーン20件（日常8／仕事6／食事・交流6）を8名の架空NPCに割り当てる
- FR12.2 各回答は：回答文／回答分類／NPCの返答／NPCの表情／解説／きずな度変化／次の会話候補を持つ
- FR12.3 回答分類（会話が続きやすい・短いが自然・会話が続きにくい）は回答前に表示せず、回答後に文章で説明
- FR12.4 今日の会話クエスト：1日1回の中心イベント・1シーン1ターン（導入）・3択・NPCとペットのきずな度を更新・同日再プレイ可・同日のきずな度重複更新禁止
- FR12.5 会話練習モード：20シーンから選択またはランダム開始・基本4ターン（導入→展開→応答→締め）・条件成立時最大1回のボーナスターン・何度でも利用可・きずな度は増減しない
- FR12.6 難易度スライダーは作らない。NPCの反応差はNPC固有の性格と関係段階で表現する
- FR12.7 ストーリー枠：練習4ターンとクエスト1ターン（導入）に「導入・展開・応答・締め」の役割を持たせ、各段階で場面カテゴリ／タグ・NPC性格・関係段階・直前の選択（facet）に合う台詞だけをデータ側の重みで抽選する
- FR12.8 直前の話を無視する台詞を排除し、同じ台詞の連続を回避する。候補が無ければその場面の正規回合→場面共通の台詞へフォールバックする
- FR12.9 回答は会話スキル（facet＝共感／質問／自己開示／丁寧な断り／自然な終了／約束／会話を続ける／回避）を持つ。複数の合理的な選択を認め、断ること自体を減点理由にしない（丁寧な断りは type を bad にしない）
- FR12.10 ペット助言は「今回のポイント＋改善例」を表示する。種別で口調を変えても、助言内容の正しさは変えない
- FR12.11 外出（ペット小屋→外へ出る）のたびに、未会いのNPCを1名ずつ発見登録する（最初は佐藤さん。以降、毎回違うNPCにも出会える）。発見したNPCは交流ノートに載り、その後の会話シーンの候補になる
- FR12.12 クエストの回合もストーリー枠（オープン役割）から条件に合う候補を重み付きで抽選し、直近に使った台詞を避けて外出のたびに変化する。候補が無ければ正規の導入台詞を使う
- FR12.13 会話クエスト・練習の画面は、背景（ピクセル風景）に「あなた・ペット・NPC」が溶け込んだ1枚の動画にする（呼吸・発言・表情のアニメーション）。NPCは8名それぞれのデザイン（髪型・服色・店員はエプロン等）で、発言中は talk、回答後は回答分類に応じた表情（happy/troubled/smile）へ変わる。`prefers-reduced-motion` では静止1コマ

### FR13 きずな度
- FR13.1 NPC好感度とペットなかよし度を共通の「きずな度」へ統合。ペット世代別・NPC別に保存
- FR13.2 NPCきずな度：初期値40／会話が続きやすい+8・短いが自然+3・会話が続きにくい−4・0〜100補正・NPCごと1日1回のみ
- FR13.3 ペットきずな度：初期値20／今日の会話クエスト完了で+2・1日1回・回答分類で差をつけない・減点なし・世代ごとに保存・旅立ち時に思い出へ保存
- FR13.4 総合きずな度 ＝ round（ペットきずな度×0.4 ＋ 対象NPCきずな度×0.6）
- FR13.5 総合きずな度は会話開始時の雰囲気・挨拶・ペット助言・特別会話解放・関係段階上昇・会話後演出・思い出に使用する。回答選択肢の評価自体は変更しない

### FR14 関係段階

| 数値 | 段階 |
| -----: | --- |
| 0〜19 | 出会ったばかり |
| 20〜39 | 少し慣れてきた |
| 40〜59 | 心が通い始めた |
| 60〜79 | 信頼し合っている |
| 80〜100 | 大切な仲間 |

### FR15 交流ノート
- FR15.1 NPCのピクセル肖像・表示名・立場・きずな度・関係段階・会話回数・最終会話日・解放済みイベント数を表示
- FR15.2 未遭遇NPCはシルエットと「？？？」で表示
- FR15.3 NPC詳細には架空の自己紹介・出会った場所・現在の関係・次の会話解放ヒントを表示。会話全文は保存しない

### FR16 ペット別コーチ台詞
- FR16.1 6種のペットは回答後に異なる話し方で助言する
- FR16.2 台詞条件：種類／コーチタイプ／成長段階／健康状態／回答分類／シーン分類／NPC関係段階／ペット関係段階／総合きずな度／イベント種別
- FR16.3 初期版100〜300件（目標150〜180件）。台詞は画面処理に直接書かず専用データファイル `js/data/pet-coach-speech.js` へ分離
- FR16.4 フォールバック：①種類＋回答分類→②コーチタイプ＋回答分類→③回答分類のみ→④共通の安全な台詞
- FR16.5 同じ台詞の短期連続を避けるため直近台詞IDを保存
- FR16.6 助言は「今回のポイント（評価）」と「改善例（具体的な言い換え）」の2部構成で表示する

### FR17 ペットライフサイクル
- FR17.1 旅立ち時に思い出へ保存：ペット名／種類／世代／誕生日／孵化日／旅立ち日／一緒に過ごした日数／最終成長段階／健康記録日数／会話クエスト完了日数／最終きずな度／主に交流したNPC
- FR17.2 旅立ち後、新しい卵・ペット名・決定方式を設定して次世代を開始

### FR18 図鑑・思い出
- FR18.1 ペット図鑑：発見済みは姿・種類名・発見日、未発見はシルエットと「？？？」。種類確定後にのみ登録。同じ種類の再取得でも初回発見日を維持
- FR18.2 思い出：世代ごとの個体記録を表示

### FR19 データ保存
- FR19.1 統一スキーマ（詳細設計書）で localStorage に保存
- FR19.2 保存失敗・破損・スキーマ不整合時の処理を実装し、破損データは隔離後に安全な初期値で起動する
- FR19.3 データ初期化前に確認表示

### FR20 研修デモツール
- FR20.1 設定画面に研修デモツールを用意し、EXP付与・日付進行・旅立ち強制などで世代循環を確認できる

## 6. 非機能要件

- **ユーザビリティ**：全画面・全操作が日本語。主要な操作はマウスとキーボード（Tab／Enter／Space）で実施できる
- **UI統一**：全画面が同じ「田園生活風ピクセル」デザイン。8pxグリッド、2/4pxの枠線、右下へずらした硬い影
- **アクセシビリティ**：本文16px以上・ボタン高さ48px以上・`focus-visible`表示・色だけで状態を表さない・エラーを文章表示・キャラクター画像へ代替テキスト・会話結果へ`aria-live="polite"`・激しい点滅不使用・文字送りはクリックで全文表示・アニメーションなしでも状態を理解可能・主要画面で文字やボタンを重ねない
- **モーション**：`prefers-reduced-motion: reduce` では動きを停止または簡略化
- **セキュリティ**：外部通信なし・ログインなし・localStorageキーを専用名前空間に限定・HTML文字列へユーザー入力を直接挿入しない・データ初期化前の確認・共有PCではローカルデータを閲覧される可能性がある旨をREADMEへ記載・リスクを「ゼロ」と表現しない
- **品質**：Chrome/Edgeでのコンソールエラーなし・Networkタブに外部アクセスなし
- **動作環境**：`kenecho-village.html` をファイルとして直接開いて動作。通信不要

## 8. セキュリティ要件

- 外部通信・外部API・CDN・外部IDBを使用しない
- ローカルデータは共有PCでは閲覧される可能性があるため、個人・勤務・顧客情報を保存しない旨をREADMEで警告
- `localStorage` キーを専用名前空間（`kenechoVillage.`）に限定
- ユーザー入力を `textContent` で表示し、`innerHTML` へ直接流さない
- データ初期化は必ず確認モーダルを挟む
- セキュリティ・プライバシーのリスクを「ゼロ」と表現しない

## 9. 受入条件

1. 初期設定と再起動後の復元が動作する
2. 食事・運動・睡眠・体重を記録・編集・削除できる
3. 過去記録がEXPやきずな度を再加算しない
4. 健康スコアとEXPが正しく計算される
5. EXPによりペットが成長する
6. 卵取得時に選択方式を選べる
7. 家を出るまでは種類が不明である
